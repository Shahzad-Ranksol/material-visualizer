# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Three customer apps from one codebase, under one brand, Hollin**: **Hollin Kitchens**, **Hollin Bathrooms** and **Hollin Fencing** configurators, each its own Vercel project with the same look and feel. A customer starts on an intro card, then answers one question per step (Hollin Kitchens first picks one of three layouts: Classic with island `kitchen`, Modern U-shape `kitchen-modern`, Galley with island `kitchen-galley`, all client renders) ("Step 2 of 6": door style, colour, worktop…) while the real photo above changes with each answer, and ends on a summary (Download, Copy link, Request a quote). Kitchen and Bathroom change **design and materials**; Fencing changes the **fence design only** (no colour step). There is **no photo upload**, no sign-in and no backend on the customer path: every item's mask and plane was cut once, offline, and committed ("baked"), and design styles were generated offline, so the apps render instantly and never run a model in the customer's browser.

**Which app a build is**: `VITE_APP=kitchen|bathroom|fencing` (default `kitchen`; unknown ids fail the build). App configs live in `apps/` (`kitchen.ts`, `fencing.ts`, `bathroom.ts`; `registry.ts` is plain data, also read by `vite.config.ts`). Each lists its brand, intro copy, `sceneIds` and `steps`. A step offers a style group's baked designs (`style`), finishes for some items (`finish.itemIds`), or both. A production build ships only the app's own `public/scenes/<id>/` and hashes only those. **Vercel**: three projects on this one repo, each with the env var `VITE_APP` set and its own domain; the build command and `vercel.json` are shared. **Bathroom** waits on the client's render: until its scene is in `scenes/scenes.ts` and baked, the bathroom app shows its intro with "Coming soon" (its materials are already in `scenes/materials.ts`; its style groups go into `scenes/styles.ts` once the scene exists, because the catalogue tests require real items).

It is a clone of the original multi-tenant material visualizer. React 19 + Vite 6 + TypeScript, flat layout (no `src/`). The old `server/` backend (Express + Prisma + MySQL) is still on disk but nothing in the frontend uses it any more.

## Commands
- `npm install`, `npm run dev` (Vite on :3000, the kitchen app unless `VITE_APP` is set), `npm run dev:kitchen|dev:bathroom|dev:fencing`, `npm run build` (honours `VITE_APP`), `npm run build:kitchen|build:bathroom|build:fencing`, `npm run preview`, `npm run typecheck`
- `npm test` — Vitest unit tests (`tests/unit/`): studio state + share links, the app configs and wizard steps (`apps.test.ts`), recipe masks + hit-testing, the scene catalogue and `scenes/baked.json` integrity, **baked-mask accuracy** (`bakedAccuracy.test.ts`, below), plus the renderer/analysis maths (colour space, mapping, plane fitting, mask ops, quality gate, recolour)
- `npm run test:e2e` — Playwright (`tests/e2e/`, 2 workers): `configurator.spec.ts` (the kitchen app on :3000 and the fencing app on :3010, both started by `playwright.config.ts`: intro → steps, finishes, every pixel outside the finished masks byte-identical to the photo, before/after, download, share link + step restored, no `/models/` request; fencing offers no finish); `kitchenColour.spec.ts` (each reference colour rendered by the studio and scored against the reference per pixel, CIEDE2000: median 1.9–3.5, p90 6–10; limits guard regressions); `golden.spec.ts` (WebGL renderer on synthetic scenes); `area-editor.spec.ts`; opt-in model specs below
- `npm run assets:fetch` — downloads the CC0 texture scans (Poly Haven; entries with `ambientcg` from ambientCG, e.g. the Crema Marble slab; `scripts/assets.manifest.json`) into `public/textures/` and the local models into `public/models/` (both git-ignored). Textures are needed by the studio; models only by the bake tool and the validation tools. Missing files under `/models/` must 404 (Vite plugin in `vite.config.ts`)
- `npm run scenes:fetch` — downloads the scene photos listed in `scenes/photos.json` into `public/scenes/<id>/photo.jpg` (+ `thumb.jpg` via ffmpeg). These are **committed**; re-run only when a photo changes (delete the old files first)
- `npm run scenes:refine [-- scene/item …]` — re-applies recipes' pixel rules (snapped `outline`, `keepColour`, `subtract`, `solid`) to the committed masks in Node, keeping their planes, no model (default: every item with `keepColour`, plus those items' style bakes). Use after tuning an outline or colour window; idempotent
- `npm run scenes:intrinsic:setup` once (Python 3.12 venv via `uv` in `scripts/intrinsic/.venv`, git-ignored; torch is pinned to 2.2.2, the last release with Intel-Mac wheels), then `npm run scenes:intrinsic [-- scene|scene/styleKey …]` — bakes each scene photo's **light** offline with Marigold-IID "lighting" (`prs-eth/marigold-iid-lighting-v1-1`, OpenRAIL++ weights / Apache-2.0 code): `public/scenes/<id>/shading.png` + `reflection.png`, and per design style the same for its rect on the composed photo (with the patch's alpha), indexed in `scenes/intrinsics.json`. CPU, minutes per image. Re-run after a photo or a style patch changes
- `npm run scenes:light [-- scene …]` — for the scenes in `LIGHT_REFINE` (`scenes/lightRefine.ts`, unit-tested; the Galley so far) moves the light Marigold left in an item's albedo into its shading: the albedo's smooth brightness (masked Gaussian of its log luminance, `sigma` px, relative to the item's median) multiplies the shading, so a new finish keeps the under-cabinet light pools and the falloff; with `near` only within that many px of the item's occluder (the toaster's contact shadow on marble, whose veins are real colour); `contrast` expands the item's light around its median (the photo is tone-mapped, so pools on near-white tile are compressed; the Galley splashback uses 1.8); `gloss` (a polished floor) blurs the albedo along the vertical, where mirror reflections are streaks and diagonal boards average out, and moves what stands brighter across into the reflection layer (`reflection.lit.png`). Reads Marigold's `shading.png`/`reflection.png`, writes the `.lit.png`s and points `scenes/intrinsics.json` at them (idempotent). Re-run after `scenes:intrinsic` (which points the index back at `shading.png`) or after the scene's masks change
- `npm run finishes:fromref` — fits the kitchen paints to the client's colour references (`tests/fixtures/kitchen-refs/`: the Classic kitchen with its cabinets painted Burgundy, Cherry Red, Burnt Orange, Charcoal and Dark Wood, pixel-aligned with our photo): per reference, the albedo that best explains it over the fronts' baked masks against the baked light (least squares), written as the flat swatch in `public/finishes/`; Dark Wood stains the walnut scan to that colour instead (`public/materials/dark_walnut_stain*.jpg`). Writes render | reference pairs and ΔE heat maps to `test-results/colour-match/`. Re-run after the kitchen photo, its bake or its light changes
- `npm run scenes:qa` — contact sheets of every scene and style with each item's painted area tinted, in `test-results/scene-qa/`, for review
- `npm run scenes:bake` — headless bake of every scene item (real models, minutes per scene; `BAKE=missing` only unbaked items, `BAKE_SCENE=kitchen` one scene). Don't edit source files while it runs: a hot reload restarts the page and stops the bake
- `npm run validation:fetch` / `validation:find` / `validation:score` — the segmentation validation set (`validation/`, approve at `/dev/validation`), unchanged from the original project

## Architecture

### Routing
`index.tsx`: `/` → `components/configurator/Intro.tsx`, `/design` → `components/configurator/Configurator.tsx`; `/studio?…` (old links) redirects to `/design?…`. Dev server only: `/dev/scenes` (bake tool), `/dev/validation`, `/dev/validation/results`.

### Scenes, items and materials (`scenes/`)
- `scenes/scenes.ts` — `SCENES`: each scene's photo (a supplied render, `source: 'client'`, or a free-licence stand-in) and `items`. An item has a `kind` (renderer surface kind), a `role` (`front`/`worktop`/`splashback`/`panel`/`fence`/`wall`/`floor` — which finishes fit it) and a bake `recipe`: the SegFormer class `label`, one SAM cut per `anchors` point (separate cabinet runs; each cut keeps only the region connected to its anchor), merged without overlap, then kept inside `clip` and outside `subtract` polygons (all coordinates are fractions of the photo). `polygonOnly` makes the item just its polygon. **The precise mode, used by every scene now, is `outline`**: the item traced as polygons in photo pixels (`px(w, h)` helpers `K`, `W`, `C`, `M`, `F`), each side snapped onto the photo's real edge (`scenes/edgeSnap.ts`, ±6 px / ±3°, sub-pixel, unit-tested) and filled anti-aliased; `subtract` polygons are snapped too. Items whose material separates from what's around it by colour (the fences) add **`keepColour`** (`keepByColour` in `scenes/recipeMask.ts`): inside the outline only pixels in the material's HSV window(s) are kept — the garden through the gaps between boards, a tree before them, a grey unit go — with small holes refilled (`maxHole`) and specks dropped (`minPiece`); `solid` outlines are exempt. Then the `anchors`' SAM cuts only supply 3D planes (empty = one plane fitted from the outline), `intersectCut` keeps only what the cut covers (gaps between fence boards), and objects in front are kept by `protect` clicks (SAM objects), `protectSoft` regions (thin things too fine for a cut — a toaster's wire handle, a twig — soft by colour distance from the region's median; `scenes:refine` adds them to the committed occluder) and `protectColour` (pixels in a hue/saturation/brightness window inside a region — green leaves before wood, a chrome ring before dark slats; `trim` cuts each kept piece, a brass knob, down to the pixels clearly more saturated than the paint around it, so no ring of old paint stays around a painted knob). Parts are a hard partition (`partitionParts`): the renderer composites parts one over another, so soft overlaps would leave outlines. Recipe points are **fractions** of the photo; the analysis worker takes **percentages** — `sceneBake.ts` converts (`workerPoint`); passing fractions straight through puts every click in the top-left corner. To trace a new render: make gridded zoom crops of it, read corners to a few px, let snapping do the rest, bake, and check full-resolution renders.
- A scene's `collection` (default its id) is the material collection it offers: the three kitchens share `kitchen`. The kitchen fronts are 16 paints (5 fitted to the client's references) and 3 woods; `FinishChoices` groups a step's swatches into Paints / Woods / Stone & tiles. Paints use the textured render on the baked light, not recolour: measured against the references both match equally, and the textured one paints over oak (the Galley) cleanly.
- `scenes/materials.ts` — `STUDIO_MATERIALS`: five per scene collection plus shared `room` wall/floor finishes, each a full renderer `Material` (physical profile from `defaultProfileFor`) with `collection`, `roles` and an optional `tag`. Scans come from `/textures/`; lacquers are flat colour swatches committed in `public/finishes/`. `materialsFor(collection, roles)` is what the finish panel offers: the scene's collection + room finishes that fit **every** selected item's role.
- `scenes/qa.ts` — the accuracy spec checked by `tests/unit/bakedAccuracy.test.ts` against the committed bake (on the composed photo for a style): per item `include`/`exclude` photo pixels that must / must not be painted (parts × (1 − occluder)) and a `foreign` colour budget (foliage inside a fence). `knownIssue` marks an explained shortfall as an expected failure (currently: the Picket style's back run, whose gaps show the shed wall in the pickets' own colour). Add points here when fixing a leak, so it can't come back.
- `scenes/baked.json` (via the typed `scenes/baked.ts`) + `public/scenes/<scene>/<item>.part<N>.png` / `<item>.occluder.png` — the baked result, written only by the bake tool and committed: per item its plane parts (white-on-black mask PNG + `SurfaceGeometry`), occluder, confidence, and whether it was hand-edited.

### The bake tool — how items are made accurate (`/dev/scenes`)
`components/dev/SceneBakePage.tsx` + `scenes/sceneBake.ts` run each recipe through the existing analysis worker (`services/roomAnalysis.ts` `cutSurface`: SegFormer + SAM 2.1 + MoGe-2, all local, see "Analysis pipeline" below), show every scene's baked items tinted over the photo, and open any item in the shared `components/AreaEditor.tsx` (Protect object, Include area, polygons, brush, undo) to correct it by hand. Save goes through `acceptedArea` (`services/areaPreview.ts`) and `POST /__scenes/save` (`scripts/sceneBakeDevServer.ts`, dev only), which writes the PNGs and upserts `scenes/baked.json`. The page reads that file through `GET /__scenes/baked` rather than importing it, so saves don't hot-reload it mid-run. Swapping in your own renders: replace the photo in `scenes/photos.json`/`public/scenes/<id>/`, adjust the recipes, re-bake that scene, then review it.

### Design styles — AI redesigns, generated offline (`/dev/styles`)
Whole-item redesigns (fence type, door style, worktop, splashback, media-wall panel) on top of finishes. `scenes/styles.ts` lists `STYLE_GROUPS` (which items a style replaces) and `STYLE_OPTIONS` (label + prompt; `recipeOverrides` per item, e.g. `intersectCut` for a picket fence's gaps); `generationPrompt` adds the shared instructions (light neutral unfinished material so finishes apply on top, same camera/light, change only the masked area).
- `components/dev/StyleLabPage.tsx` + `scenes/styleGen.ts`: the region is the group's baked item masks, grown 6 px, **minus their occluders** (objects in front stay the photo's own pixels). The photo is letterboxed (never stretched) to the provider's shape and sent with the mask to `POST /__styles/generate` (`scripts/sceneBakeDevServer.ts`, server-side; `GEMINI_API_KEY` → Gemini image editing, else `OPENAI_API_KEY` → `gpt-image-1` masked edit; `GEMINI_IMAGE_MODEL`/`OPENAI_IMAGE_MODEL` override). Candidates are cropped back, colour-matched on a ring outside the region (`seamGain`) and blended with an edge feathered *inside* the region (`scenes/styleBlend.ts`, unit-tested: pixels outside are byte-identical). Picking a candidate ("Use this") is the quality gate: its cropped RGBA patch is saved (`POST /__styles/save` → `public/scenes/<scene>/styles/<group>--<option>/patch.webp`, `scenes/styles.baked.json`) and every item of the group is re-baked on the new design with the normal bake pipeline (`saveBakedItem(..., { styleKey })`).
- A style whose committed design was made on an older photo of its scene carries `stale` (`scenes/styles.ts`) and is not offered (`styleBake` returns nothing for it, so share links drop it too) until it is generated again: the Classic kitchen's Thick stone worktop and three splashback styles, made on the photo with the vases. The door styles (Slab, Fluted) were re-baked on the new photo with their committed patches, no AI needed: run the group's items through `bakeItem` on photo + patch, with the base item's occluder, and `saveBakedItem(..., { styleKey })`.
- Fence styles are keyed by colour (`PALE_TIMBER` override in `scenes/styles.ts`, which also accepts cedar for runs the AI left as they were) over the item's outline grown a few px where the patch is the AI's; `npm run scenes:refine` re-derives them from the committed patches without regenerating.
- Studio: `state.styles` (group → option, absent = as designed; in the share link as `styles=`). `useComposedScene` draws the chosen patches over the photo (lossless PNG, cached per combination) and returns the styles actually **drawn** in that picture; masks (`useSceneMasks`, `useLookRender` via `scenes/lookLayers.ts`) follow the drawn styles, never chosen ones still loading or failed, so a style's masks never sit over the unstyled photo; `bakedItemFor` (`scenes/stylesBaked.ts`) gives each item the chosen style's masks, so finishes, hover and selection follow the new shape. The configurator's `StyleChoices` shows only styles generated *and* baked for every item of the group, previewed by layering the patch over the photo in CSS; a soft light sweep plays over the changed area once the new design is on screen.

### The configurator (`components/configurator/`, built on `components/studio/`)
- `wizard.ts` (unit-tested) turns the app's steps into the scene's **ready** steps: a style step only if its group has designs baked for every item (`readyStyles`), a finish step only for baked items with fitting materials (`materialsFor`); empty steps drop out; a `scene` step is added first when an app has several scenes; `summary` comes last. It also gives the look chip text (`lookLabel`), the step a tap on an item jumps to (`stepOfItem`) and the items a step changes (outlined in brass for a moment when it opens).
- `Configurator.tsx` holds the reducer and wires `useComposedScene` → `useSceneMasks` → `useLookRender` → `SceneCanvas`. Phones: brand bar + progress segments, the picture pinned under it, the step below, Back / Next fixed at the bottom. Wide screens: the picture on the left, the step card with its Back / Next on the right. `StyleChoices` (design cards cropped from the photo + patch), `FinishChoices` (swatches; tapping the chosen one again takes it off), `SummaryStep` (each choice, tap to edit; Download, Copy link, Request a quote to `APP.quoteEmail`, Start over), `BrandBar`, `Intro`.
- Finish steps dispatch `assign` (all the step's items at once); the URL carries `scene`, `styles`, `look` and `step`, and the share link opens on the summary. Only the app's scenes (`scenes/appScenes.ts`) are accepted from a link.

### The picture (`components/studio/`)
- No tint on the picture: the item under the pointer gets a fine white outline and its name, selected items a fine brass one (`SceneCanvas`). A finish just applied is **rolled on** over its items: `components/studio/paintReveal.ts` (unit-tested) lays 3–7 overlapping lanes along the area's longer side, alternating direction, with a soft wavy wet edge (`PAINT_MS`); `SceneCanvas` draws the new look through those strokes ∩ the items' masks on a canvas, then promotes it and a wet sheen passes over the area. Any other new look (remove, reset, style, scene switch, `prefers-reduced-motion`) fades in.
- State is one reducer (`scenes/studioState.ts`): `{ sceneId, selected[], assignments: itemId → materialId }`. A canvas click selects one item (Shift/⌘/Ctrl adds), item chips toggle (multi-select), "Select all" takes every baked item; applying a finish assigns it to every selected item. The look is mirrored into the URL (`?scene=kitchen&look=island:kit-navy-lacquer,…`) — that's the share link, and a reload restores it.
- `useSceneMasks` loads the scene's baked masks once (downscaled to 800 px) for hover hit-testing (`hitTest` in `scenes/recipeMask.ts`: the smallest item under the pointer wins) and the hover outline in `SceneCanvas`.
- **Baked light** (`scenes/bakedLight.ts`, `services/renderer/intrinsics.ts`): `useComposedScene` also returns the picture's baked light (the scene's shading/reflection with each drawn style's drawn over it); `renderMaterial(..., { bakedLight })` then renders new albedo × the photo's own diffuse shading + its reflection (scaled by the finish's gloss) instead of the light estimated from the surface's average colour (`recoverLighting`, still the fallback when a scene or a drawn style has none). Recolour uses it too: the old albedo is (photo − reflection) / shading, the new pixel target × shading + reflection, so the swatch is exactly the new albedo (unit-tested to ΔE < 2). `?light=recovered` in the studio URL renders with the old estimate, for comparison.
- `useLookRender` renders every assigned item's parts (`lookLayers`) as layers in **one** `renderMaterial(scene.photo, layers)` call. Fences (`role: 'fence'`) and AI-styled items are **recoloured**, not textured: the real boards, gaps and grain stay and take the finish's colour (`services/renderer/recolor.ts`: out = target × L / median L over all the item's parts together, so sun and shade between runs survive, with a quarter of the old hue variation) and caches looks (LRU, 24) so going back is instant. `SceneCanvas` has a compare mode (drag handle: original left, your design right). 
- Visual language (light editorial): warm paper ground `paper` #f6f3ec, `mist` fills, hairline `line` #ddd7ca, spruce ink `spruce` #1e2b29 / `spruce-soft`, brass accents and selection `brass` #a9824a; Playfair Display (`font-serif`) for display headings, Familjen Grotesk (`font-grotesk`) for the UI. Tokens and keyframes (`wet-sheen`, `pop-in`, `sheet-in`, `style-sweep`) live in `index.html`. All three apps use it; the dev pages keep the old dark theme.

### Renderer (`services/renderer/`)
Unchanged single render path, `renderMaterial(roomUrl, layers, settings)`. It takes `RenderableSurface`s (mask, optional occluder mask, plane) and never guesses from a label: with no usable mask or geometry it throws `NeedsSurfaceReviewError`. WebGL2: each masked pixel's camera ray meets the surface plane (or a homography fallback) to get real millimetres (`surfaceMapping.ts`, mirrored in `material.frag.glsl`); the albedo is laid out at its physical size and repeat mode, shaded in linear light with the photo's recovered illumination (`lightingRecovery.ts`: on coloured old paint only brightness carries over, and fine variation below `DETAIL_TEXTURE_THRESHOLD` — the old surface's grain — is dropped so it doesn't print through the new finish); occluders are restored exactly and every pixel outside the masks is byte-identical to the original. An occluder's rim (a baked occluder is hard and grown a pixel past its object) is matted against the surface (`occluderMatte.ts`, unit-tested): within 3 px of its edge each pixel is explained as object + old surface from the local colours, the occluder there becomes that alpha and only the old surface's share is swapped for the new finish, so no ring of white tile stays around a toaster on dark concrete. Output is a lossless PNG object URL. A mask must match the photo's shape. The design contract is `Material_Visualizer_Market_Ready_Rendering_Plan.md`.

### Analysis pipeline (bake time and validation only)
`services/roomAnalysis.ts` → Web Worker `workers/analysis.worker.ts`, models served from `public/models/`, outputs cached in IndexedDB per image + `ANALYSIS_VERSION`. SegFormer-B2 (ADE20K) proposes classes, MoGe-2 recovers 3D geometry, SAM 2.1 cuts a surface from positive/negative prompts; other structural surfaces' and objects' confident interiors are hard limits, the loose edge band is re-decided by colour, skirting removed, one plane fitted per physical surface (`services/surfacePlaneFit.ts`), mirrors and thin objects excluded, countertops found by geometry when SegFormer mislabels them (`services/analysis/countertop.ts`), and a composite confidence scored by `services/qualityGate.ts`. Jobs take `{ signal, onProgress }` and have hard time limits (`services/analysis/workerClient.ts`). The Area Editor's tools all edit the mask directly (`services/areaMaskOps.ts`, unit-tested).

`constants.ts` (the original `MATERIALS`/`CURATED_ROOMS`) survives only for the validation/evidence tooling (`tests/e2e/pipeline-evidence.spec.ts`).
