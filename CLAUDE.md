# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Finish Studio**: a preset-scene material visualizer. Customers pick one of five fixed scenes (Kitchen, Fencing, Media Wall, Cabinets, Wardrobe), click one or several items in it (cabinet fronts, worktop, fence run, feature panel…) and try finishes on them. There is **no photo upload**, no sign-in and no backend on the customer path: every item's mask and plane was cut once, offline, and committed ("baked"), so the studio renders instantly and never runs a model in the customer's browser.

It is a clone of the original multi-tenant material visualizer. React 19 + Vite 6 + TypeScript, flat layout (no `src/`). The old `server/` backend (Express + Prisma + MySQL) is still on disk but nothing in the frontend uses it any more.

## Commands
- `npm install`, `npm run dev` (Vite on :3000), `npm run build`, `npm run preview`, `npm run typecheck`
- `npm test` — Vitest unit tests (`tests/unit/`): studio state + share links, recipe masks + hit-testing, the scene catalogue and `scenes/baked.json` integrity, plus the renderer/analysis maths (colour space, mapping, plane fitting, mask ops, quality gate)
- `npm run test:e2e` — Playwright (`tests/e2e/`, 2 workers): `preset-studio.spec.ts` (the customer flow on the baked kitchen: canvas click + chip multi-select, finishes, every pixel outside the finished masks byte-identical to the photo, compare, download, share link, no `/models/` request); `golden.spec.ts` (WebGL renderer on synthetic scenes); `area-editor.spec.ts`; opt-in model specs below
- `npm run assets:fetch` — downloads the CC0 texture scans (Poly Haven, `scripts/assets.manifest.json`) into `public/textures/` and the local models into `public/models/` (both git-ignored). Textures are needed by the studio; models only by the bake tool and the validation tools. Missing files under `/models/` must 404 (Vite plugin in `vite.config.ts`)
- `npm run scenes:fetch` — downloads the scene photos listed in `scenes/photos.json` into `public/scenes/<id>/photo.jpg` (+ `thumb.jpg` via ffmpeg). These are **committed**; re-run only when a photo changes (delete the old files first)
- `npm run scenes:bake` — headless bake of every scene item (real models, minutes per scene; `BAKE=missing` only unbaked items, `BAKE_SCENE=kitchen` one scene). Don't edit source files while it runs: a hot reload restarts the page and stops the bake
- `npm run validation:fetch` / `validation:find` / `validation:score` — the segmentation validation set (`validation/`, approve at `/dev/validation`), unchanged from the original project

## Architecture

### Routing
`index.tsx`: `/` → `components/LandingPage.tsx` (the five scenes, each linking to `/studio?scene=<id>`), `/studio` → `App.tsx`. Dev server only: `/dev/scenes` (bake tool), `/dev/validation`, `/dev/validation/results`.

### Scenes, items and materials (`scenes/`)
- `scenes/scenes.ts` — `SCENES`: each scene's photo (a supplied render, `source: 'client'`, or a free-licence stand-in) and `items`. An item has a `kind` (renderer surface kind), a `role` (`front`/`worktop`/`splashback`/`panel`/`fence`/`wall`/`floor` — which finishes fit it) and a bake `recipe`: the SegFormer class `label`, one SAM cut per `anchors` point (separate cabinet runs; each cut keeps only the region connected to its anchor), merged without overlap, then kept inside `clip` and outside `subtract` polygons (all coordinates are fractions of the photo). `polygonOnly` makes the item just its polygon. **The precise mode, used by every scene now, is `outline`**: the item traced as polygons in photo pixels (`px(w, h)` helpers `K`, `W`, `C`, `M`, `F`), each side snapped onto the photo's real edge (`scenes/edgeSnap.ts`, ±6 px / ±3°, sub-pixel, unit-tested) and filled anti-aliased; `subtract` polygons are snapped too. Then the `anchors`' SAM cuts only supply 3D planes (empty = one plane fitted from the outline), `intersectCut` keeps only what the cut covers (gaps between fence boards), and objects in front are kept by `protect` clicks (SAM objects) and `protectColour` (pixels in a hue/saturation/brightness window inside a region — green leaves before wood, a chrome ring before dark slats). Parts are a hard partition (`partitionParts`): the renderer composites parts one over another, so soft overlaps would leave outlines. Recipe points are **fractions** of the photo; the analysis worker takes **percentages** — `sceneBake.ts` converts (`workerPoint`); passing fractions straight through puts every click in the top-left corner. To trace a new render: make gridded zoom crops of it, read corners to a few px, let snapping do the rest, bake, and check full-resolution renders.
- `scenes/materials.ts` — `STUDIO_MATERIALS`: five per scene collection plus shared `room` wall/floor finishes, each a full renderer `Material` (physical profile from `defaultProfileFor`) with `collection`, `roles` and an optional `tag`. Scans come from `/textures/`; lacquers are flat colour swatches committed in `public/finishes/`. `materialsFor(collection, roles)` is what the finish panel offers: the scene's collection + room finishes that fit **every** selected item's role.
- `scenes/baked.json` (via the typed `scenes/baked.ts`) + `public/scenes/<scene>/<item>.part<N>.png` / `<item>.occluder.png` — the baked result, written only by the bake tool and committed: per item its plane parts (white-on-black mask PNG + `SurfaceGeometry`), occluder, confidence, and whether it was hand-edited.

### The bake tool — how items are made accurate (`/dev/scenes`)
`components/dev/SceneBakePage.tsx` + `scenes/sceneBake.ts` run each recipe through the existing analysis worker (`services/roomAnalysis.ts` `cutSurface`: SegFormer + SAM 2.1 + MoGe-2, all local, see "Analysis pipeline" below), show every scene's baked items tinted over the photo, and open any item in the shared `components/AreaEditor.tsx` (Protect object, Include area, polygons, brush, undo) to correct it by hand. Save goes through `acceptedArea` (`services/areaPreview.ts`) and `POST /__scenes/save` (`scripts/sceneBakeDevServer.ts`, dev only), which writes the PNGs and upserts `scenes/baked.json`. The page reads that file through `GET /__scenes/baked` rather than importing it, so saves don't hot-reload it mid-run. Swapping in your own renders: replace the photo in `scenes/photos.json`/`public/scenes/<id>/`, adjust the recipes, re-bake that scene, then review it.

### Design styles — AI redesigns, generated offline (`/dev/styles`)
Whole-item redesigns (fence type, door style, worktop, splashback, media-wall panel) on top of finishes. `scenes/styles.ts` lists `STYLE_GROUPS` (which items a style replaces) and `STYLE_OPTIONS` (label + prompt; `recipeOverrides` per item, e.g. `intersectCut` for a picket fence's gaps); `generationPrompt` adds the shared instructions (light neutral unfinished material so finishes apply on top, same camera/light, change only the masked area).
- `components/dev/StyleLabPage.tsx` + `scenes/styleGen.ts`: the region is the group's baked item masks, grown 6 px, **minus their occluders** (objects in front stay the photo's own pixels). The photo is letterboxed (never stretched) to the provider's shape and sent with the mask to `POST /__styles/generate` (`scripts/sceneBakeDevServer.ts`, server-side; `GEMINI_API_KEY` → Gemini image editing, else `OPENAI_API_KEY` → `gpt-image-1` masked edit; `GEMINI_IMAGE_MODEL`/`OPENAI_IMAGE_MODEL` override). Candidates are cropped back, colour-matched on a ring outside the region (`seamGain`) and blended with an edge feathered *inside* the region (`scenes/styleBlend.ts`, unit-tested: pixels outside are byte-identical). Picking a candidate ("Use this") is the quality gate: its cropped RGBA patch is saved (`POST /__styles/save` → `public/scenes/<scene>/styles/<group>--<option>/patch.webp`, `scenes/styles.baked.json`) and every item of the group is re-baked on the new design with the normal bake pipeline (`saveBakedItem(..., { styleKey })`).
- Studio: `state.styles` (group → option, absent = as designed; in the share link as `styles=`). `useComposedScene` draws the chosen patches over the photo (lossless PNG, cached per combination); `bakedItemFor` (`scenes/stylesBaked.ts`) gives each item the chosen style's masks, so finishes, hover and selection follow the new shape. `StylePicker` shows only styles generated *and* baked for every item of the group, previewed by layering the patch over the photo in CSS; a soft light sweep plays over the changed area once the new design is on screen.

### The studio (`App.tsx`, `components/studio/`)
- No tint on the picture: the item under the pointer gets a fine outline and its name, and a new look fades in over the previous one (`SceneCanvas`).
- State is one reducer (`scenes/studioState.ts`): `{ sceneId, selected[], assignments: itemId → materialId }`. A canvas click selects one item (Shift/⌘/Ctrl adds), item chips toggle (multi-select), "Select all" takes every baked item; applying a finish assigns it to every selected item. The look is mirrored into the URL (`?scene=kitchen&look=island:kit-navy-lacquer,…`) — that's the share link, and a reload restores it.
- `useSceneMasks` loads the scene's baked masks once (downscaled to 800 px) for hover hit-testing (`hitTest` in `scenes/recipeMask.ts`: the smallest item under the pointer wins) and the hover outline in `SceneCanvas`.
- `useLookRender` renders every assigned item's parts as layers in **one** `renderMaterial(scene.photo, layers)` call and caches looks (LRU, 24) so going back is instant. `SceneCanvas` has a compare mode (drag handle: original left, your design right). `FinishPanel` shows sample-chip swatches; `DesignSummary` lists item → finish with remove, Start over, Download (PNG), Copy link and Request a quote (mailto with the spec and link).
- Visual language: plaster ground `plaster` #e3e6e2, spruce ink `spruce` #1e2b29 / `spruce-soft`, brass selection `brass` #a9824a; Familjen Grotesk (`font-grotesk`). Tokens live in the Tailwind CDN config in `index.html`. The dev pages keep the old dark theme.

### Renderer (`services/renderer/`)
Unchanged single render path, `renderMaterial(roomUrl, layers, settings)`. It takes `RenderableSurface`s (mask, optional occluder mask, plane) and never guesses from a label: with no usable mask or geometry it throws `NeedsSurfaceReviewError`. WebGL2: each masked pixel's camera ray meets the surface plane (or a homography fallback) to get real millimetres (`surfaceMapping.ts`, mirrored in `material.frag.glsl`); the albedo is laid out at its physical size and repeat mode, shaded in linear light with the photo's recovered illumination (`lightingRecovery.ts`: on coloured old paint only brightness carries over, and fine variation below `DETAIL_TEXTURE_THRESHOLD` — the old surface's grain — is dropped so it doesn't print through the new finish); occluders are restored exactly and every pixel outside the masks is byte-identical to the original. Output is a lossless PNG object URL. A mask must match the photo's shape. The design contract is `Material_Visualizer_Market_Ready_Rendering_Plan.md`.

### Analysis pipeline (bake time and validation only)
`services/roomAnalysis.ts` → Web Worker `workers/analysis.worker.ts`, models served from `public/models/`, outputs cached in IndexedDB per image + `ANALYSIS_VERSION`. SegFormer-B2 (ADE20K) proposes classes, MoGe-2 recovers 3D geometry, SAM 2.1 cuts a surface from positive/negative prompts; other structural surfaces' and objects' confident interiors are hard limits, the loose edge band is re-decided by colour, skirting removed, one plane fitted per physical surface (`services/surfacePlaneFit.ts`), mirrors and thin objects excluded, countertops found by geometry when SegFormer mislabels them (`services/analysis/countertop.ts`), and a composite confidence scored by `services/qualityGate.ts`. Jobs take `{ signal, onProgress }` and have hard time limits (`services/analysis/workerClient.ts`). The Area Editor's tools all edit the mask directly (`services/areaMaskOps.ts`, unit-tested).

`constants.ts` (the original `MATERIALS`/`CURATED_ROOMS`) survives only for the validation/evidence tooling (`tests/e2e/pipeline-evidence.spec.ts`).
